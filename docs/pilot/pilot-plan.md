# 시범 사용 운영 절차 (v0.8 웹 버전)

작성일 `2026-09-27`, 웹 버전으로 개정 `2026-09-28`. 대상은 시범을 운영하는 사람이다. 근거 결정은 [D016~D022](../decisions.md), 웹 버전 상태는 [v0.8 검증 기록](../verification-v0.8.md)이다. 아래의 인원·시간·관찰 항목은 작업자가 정한 초안이며 확정된 연구 설계가 아니다.

## 1. 목적과 범위

시범의 목적은 학생이 주소를 여는 것부터 첫 계획, 다음 날 복귀, 지난 날 확인, 백업까지 혼자 진행할 때 **어디서 막히는지**를 찾는 것이다. 학습효과, 임용시험 성과, 만족도 점수는 측정하지 않는다. 참여자가 2~3명이라 그런 주장을 뒷받침할 수 없다.

관찰 대상은 주소 열기와 즐겨찾기, PDF 등록과 추출 검토 화면, 오늘 시작과 시간 기록, 다음 날 다시 배정, 학습 캘린더의 날짜 확인, 백업 파일 저장·불러오기다. 스캔 PDF 인식(OCR)과 LLM 계정 연결은 없다. 스캔 쪽은 `글자 없음`으로 표시만 한다. 참여자가 이 기능을 찾는지는 관찰해서 다음 구현 순서를 정하는 근거로 쓴다.

## 2. 시작 전 조건

1. **배포 시험 통과.** GitHub Actions `pages` 실행이 성공한 판만 학생이 본다. 이 실행은 단위 시험과 Chrome·WebKit 학생 흐름 시험이 통과해야 사이트를 바꾼다. 시범 직전에 배포된 주소로 `node scripts/browser-web.mjs chrome webkit --url <주소>`를 한 번 더 돌린다.
2. **전달 경로는 주소 하나.** 학생에게 `https://jinmin75.github.io/Challenge-Master/`와 [웹 가이드](guide/guide-web.html)의 PDF를 준다. 설치파일은 주지 않는다(D022). 이 주소는 공개 저장소의 공개 사이트이며 앱 코드만 있다. 학생 기록은 각자의 브라우저에만 생긴다.
3. **브라우저 조건.** 시험한 것은 Windows의 Chrome과 Playwright의 WebKit(Safari 엔진)이다. 실제 Safari·Edge·Firefox와 휴대폰·태블릿은 시험하지 않았다. Safari 16 이하는 영구 저장 요청을 지원하지 않는다(WebKit 문서, Safari 17부터 지원). 첫 Safari 참여자에게서 화면을 관찰한다.
4. **운영자가 할 일은 주소 전달뿐이다.** 운영자 PC에 설치하거나 경고 화면을 캡처할 필요가 없다. 학생의 기록은 운영자 PC·계정·저장소에 저장되지 않는다(D022 사용자 조건).

## 3. 기록 보관 조건

기록은 학생 브라우저의 저장소(IndexedDB)에만 있다. 다음 경우 학생 화면에서 기록이 보이지 않는다.

- 다른 브라우저, 다른 컴퓨터, 시크릿 창에서 열었을 때
- 학생이 브라우저의 사이트 데이터를 지웠을 때
- 브라우저가 저장 공간 부족이나 오래 방문하지 않은 사이트를 이유로 데이터를 정리했을 때(WebKit 문서의 eviction 조건). 앱은 첫 등록 때 영구 저장을 요청하지만 브라우저가 거절할 수 있다

대비책은 **백업 파일**이다. 앱은 백업 파일을 한 번도 저장하지 않았거나 마지막 저장 뒤 7일이 지나면 화면 맨 위에 안내를 띄운다. 7일은 작업자가 정한 초기값이며 시범 뒤 조정한다. 첫 사용 관찰 때 참여자가 백업 파일을 한 번 저장하고, 그 파일이 어디에 저장됐는지 찾게 한다.

설치판 0.7.0은 저장소와 GitHub Actions 결과물에 예비로만 남는다. 공유폴더에는 두지 않는다.

## 4. 진행 순서 (제안값)

| 단계 | 시점 | 방식 | 운영자가 할 일 |
|---|---|---|---|
| 사전 안내 | 1일차 전 | 대면 또는 메신저 | 목적 설명, 주소와 웹 가이드 PDF 전달, 한 브라우저로만 쓴다는 점 안내 |
| 첫 사용 관찰 | 1일차, 20~30분 | 대면 또는 화면 공유(녹화하지 않음) | 주소 안내만 주고 지켜본다. 참여자가 도움을 청하기 전에는 개입하지 않는다. 끝에 백업 파일을 한 번 저장하게 한다 |
| 혼자 사용 | 2~7일차 | 참여자 단독 | 사용 빈도는 요청하지 않는다. 운영자는 연락을 기다린다 |
| 마무리 면담 | 7일차 전후, 20~30분 | 대면 또는 화면 공유(녹화하지 않음) | 면담 질문(6절). 계속 쓸지, 기록을 지울지는 참여자가 정한다 |

첫 사용에 쓸 PDF는 참여자가 이용 권한을 가진 자료로 한다. 운영자가 교재 파일을 나눠 주지 않는다. 텍스트를 선택할 수 있는 PDF에서만 추출이 된다는 점과 50MB·30쪽 제한을 미리 알린다.

## 5. 관찰 기록 항목

첫 사용 관찰에서는 아래를 시간과 함께 적는다. 참여자의 PDF 내용, 답안, 화면에 보이는 교재 원문은 적지 않는다.

- 사용한 운영체제와 브라우저(이름과 버전), 주소를 연 방법, 즐겨찾기를 했는지
- **공부 범위** 칸을 가이드와 화면 도움말만으로 채웠는지
- PDF 등록에 걸린 시간(쪽 수와 함께), 오래 걸리거나 멈춘 경우 그 원문
- **이 설정으로 시작** 다음에 **오늘 시작**을 스스로 찾았는지
- **PDF 추출 검토**의 `원본 대조 필요` 표시를 어떻게 이해했는지
- 백업 파일을 저장한 뒤 파일을 찾았는지, 어디에 옮겨 두었는지
- 도움을 요청한 지점과 요청 내용, 운영자가 개입한 지점, 오류 메시지 원문

## 6. 마무리 면담 질문

1. 첫날 이후 앱을 연 날과 그 이유, 열지 않은 날과 그 이유
2. 다음 날 **남은 과업 다시 배정**으로 계획을 이어 갈 수 있었는지, 같은 브라우저로 열었는지
3. 학습 캘린더에서 기록 없는 날을 확인했는지, 확인하면서 불편하거나 망설인 점
4. 오늘 계획과 이번 주 예측이 실제 공부 계획에 쓸모가 있었는지, 어떤 점이 달랐는지
5. 백업 안내를 보고 백업 파일을 저장했는지, 저장하지 않았다면 이유
6. 스캔 PDF 인식이나 AI 계정 연결이 없어서 불편했던 순간이 있었는지
7. 계속 쓸지, 이 브라우저의 기록을 지울지

## 7. 기록과 개인정보

학생의 자료 설정, 계획·공부 기록, PDF에서 뽑은 글자는 학생 브라우저에만 있다. PDF 원본은 저장하지 않는다. 앱은 이 자료를 어디로도 보내지 않으며, 사이트를 제공하는 GitHub Pages에도 학생 자료가 전송되지 않는다(페이지 파일을 받아 가는 요청만 있다). 다만 GitHub은 Pages 사이트 방문자의 IP 주소를 보안 목적으로 기록·보관한다(`2026-09-28` GitHub Docs 「What is GitHub Pages?」 확인). 학생에게 사전 안내 때 알린다. 운영자가 보관하는 것은 관찰 메모와 참여자가 직접 보낸 화면 캡처·오류 원문뿐이다. 백업 파일은 참여자 소유이며 운영자가 받지 않는다.

관찰 메모에는 참여자 이름 대신 P1·P2·P3를 쓴다. 이 저장소는 공개 저장소다. 관찰 메모, 참여자가 보낸 캡처는 **저장소 밖**에 두거나, 저장소 안에 둘 경우 `docs/pilot/private/`에만 둔다(`.gitignore`의 `private/`가 이 폴더를 제외한다). 커밋 전에는 변경 파일 목록을 직접 확인한다. 시범 결과는 식별 정보를 뺀 요약만 `docs/`에 남긴다.

## 8. 중단과 종료

다음 중 하나가 생기면 해당 참여자의 시범을 멈추고 원인을 먼저 고친다.

- 참여자의 브라우저에서 주소가 열리지 않거나 등록이 되지 않을 때
- 학습 기록이 사라지거나 다른 자료와 섞였을 때(백업 파일로 되돌릴 수 있었는지도 적는다)
- 참여자가 부담을 이유로 중단을 원할 때(이유를 묻지 않는다)

시범은 모든 참여자가 첫 계획·다시 배정·날짜 확인·백업 저장을 한 번씩 해 보았거나, 막힌 지점이 기록되었을 때 끝난다. 끝나면 [작업 상태](../status.md)에 결과 요약을 남기고, 되돌리기 기능, 점검 신호 초기값, OCR과 계정 연결의 순서를 다시 결정한다.
