# 시범 사용 운영 절차 (v0.5)

작성일 `2026-09-27`. 대상은 시범을 운영하는 사람이다. 근거 결정은 [D016·D017](../decisions.md), 설치본 상태는 [v0.5 검증 기록](../verification-v0.5.md)이다. 아래의 인원·시간·관찰 항목은 작업자가 정한 초안이며 확정된 연구 설계가 아니다.

## 1. 목적과 범위

시범의 목적은 학생이 설치부터 첫 계획, 다음 날 복귀, 제거까지 혼자 진행할 때 **어디서 막히는지**를 찾는 것이다. 학습효과, 임용시험 성과, 만족도 점수는 측정하지 않는다. 참여자가 2~3명이라 그런 주장을 뒷받침할 수 없다.

관찰 대상은 설치 과정, PDF 등록과 추출 검토 화면, 오늘 시작과 시간 기록, 다음 날 다시 배정, 제거 화면의 기록 삭제 선택이다. 스캔 PDF 인식과 LLM 계정 연결은 v0.5에 없다. 참여자가 이 기능을 찾는지는 관찰해서 다음 구현 순서를 정하는 근거로 쓴다.

## 2. 시작 전 조건

1. **깨끗한 환경 시험 통과.** 운영 PC에서 Windows 샌드박스를 켜고 `npm run test:sandbox`가 `passed: true`로 끝나야 한다. 실패하면 시범을 시작하지 않는다. `2026-09-27` v0.5.0 설치파일로 통과했다. 이 시험은 무인 설치이므로 Windows 경고 화면은 확인하지 못한다.
2. **전달 경로는 구글 드라이브 공유 링크.** 모든 참여자에게 같은 링크를 준다. 링크로 내려받은 파일에는 인터넷에서 받은 파일이라는 표시가 붙어, 드라이브·브라우저·Windows의 경고가 나타날 수 있다(`확인 필요`). 다시 빌드해도 공유 파일이 바뀌지 않도록, 배포할 설치파일은 `dist/`를 직접 공유하지 않고 별도 공유 폴더에 복사해 올린다.
3. **운영자 직접 설치.** 2항의 **드라이브 링크로 내려받은** 설치파일을 운영자 PC에서 설치·실행·제거하면서 브라우저 다운로드 경고, Windows 경고 창, 설치 마법사, 제거 화면을 캡처한다. 직접 빌드한 파일을 그대로 실행하면 학생이 보는 경고가 재현되지 않을 수 있다. 제거 화면의 삭제 칸을 시험하기 전에는 운영자 PC에 `%LOCALAPPDATA%\ChallengeMaster`가 없는지 먼저 확인한다. 폴더가 있으면 삭제 칸 시험은 하지 않는다.
4. **학생 안내 확정.** 3항의 캡처로 [학생 설치 안내](student-install-guide.md)의 `확인 필요` 표기를 모두 바꾸고 드라이브 링크를 넣은 뒤에 배포한다. 표기가 남은 안내는 배포하지 않는다.
5. **설치파일 확인값.** `dist/Challenge-Master-Setup-0.5.0-win-x64.exe.sha256`의 값이 [v0.5 검증 기록](../verification-v0.5.md)의 SHA-256과 같은지 확인한다. 첫 사용 관찰 때 학생 PC에서 PowerShell `Get-FileHash <파일 경로>`로 같은 값인지 대조한다.
6. **참여자 PC 조건.** 확인된 환경은 Windows 11 x64다. Windows 10, ARM PC, S 모드 PC는 확인하지 않았다.

## 3. 스마트 앱 컨트롤 확인

Microsoft 지원 문서에 따르면, 스마트 앱 컨트롤은 서명되지 않았거나 서명이 잘못된 앱을 신뢰할 수 없는 앱으로 보고 차단한다. 문서는 개별 앱에 예외를 줄 방법이 현재 없다고 밝힌다(`2026-09-27` 확인, [스마트 앱 컨트롤 FAQ](https://support.microsoft.com/ko-kr/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)). v0.5 설치파일과 제거 프로그램은 서명되지 않았다.

이 확인은 드라이브 링크를 보내기 **전에** 한다. 상태 이름과 동작은 위 문서에 나오지 않으므로 아래 구분은 `확인 필요`다.

- **꺼짐:** 참여 가능하다.
- **켜짐 또는 평가:** 설치가 막힐 수 있다. 참여자에게 이 기능을 끄라고 요구하지 않으며, 서명판이 나올 때까지 해당 참여자는 제외하는 것을 기본으로 한다.

같은 문서는 최근 Windows 업데이트부터 클린 설치 없이 Windows 보안 앱에서 이 기능을 다시 켤 수 있다고 밝힌다. 참여자가 스스로 이 기능을 다시 켜려 한다면 서명 없는 제거 프로그램이 막힐 수 있으므로(`확인 필요`) 먼저 앱을 제거하도록 안내한다. 마무리 면담 때 설정 상태를 한 번 더 적는다.

## 4. 진행 순서 (제안값)

| 단계 | 시점 | 방식 | 운영자가 할 일 |
|---|---|---|---|
| 사전 확인 | 1일차 전 | 대면 또는 메신저 | 목적 설명, 스마트 앱 컨트롤 확인(3절), 드라이브 링크와 학생 설치 안내 전달 |
| 첫 사용 관찰 | 1일차, 30~40분 | 대면 또는 화면 공유(녹화하지 않음) | 설치파일 확인값 대조 후 설치 안내만 주고 지켜본다. 참여자가 도움을 청하기 전에는 개입하지 않는다 |
| 혼자 사용 | 2~7일차 | 참여자 단독 | 사용 빈도는 요청하지 않는다. 운영자는 연락을 기다린다 |
| 마무리 면담 | 7일차 전후, 20~30분 | 대면 또는 화면 공유(녹화하지 않음) | 면담 질문(6절), 제거 여부와 기록 삭제 선택을 참여자가 정한다 |

첫 사용에 쓸 PDF는 참여자가 이용 권한을 가진 자료로 한다. 운영자가 교재 파일을 나눠 주지 않는다. 텍스트를 선택할 수 있는 PDF에서만 추출이 된다는 점과 32MB·30쪽 제한을 미리 알린다.

## 5. 관찰 기록 항목

첫 사용 관찰에서는 아래를 시간과 함께 적는다. 참여자의 PDF 내용, 답안, 화면에 보이는 교재 원문은 적지 않는다.

- 설치파일 실행부터 첫 화면이 열릴 때까지 걸린 시간, 경고가 떴는지, 참여자가 어떻게 통과했는지
- **공부 범위** 칸을 설치 안내와 화면 도움말만으로 채웠는지
- **이 설정으로 시작** 다음에 **오늘 시작**을 스스로 찾았는지
- **PDF 추출 검토**의 `원본 대조 필요` 표시를 어떻게 이해했는지. 이 화면은 쪽 번호와 상태만 보여 주고, 스캔 쪽도 `추출 초안`으로 표시한다(알려진 결함). 실제 추출 여부는 참여자가 허락하면 기록 폴더의 추출 초안 파일에서 확인한다
- 도움을 요청한 지점과 요청 내용, 운영자가 개입한 지점
- 오류 메시지 원문. 앱이 열리지 않으면 `%LOCALAPPDATA%\ChallengeMaster\startup-error.log`가 생겼는지

## 6. 마무리 면담 질문

1. 첫날 이후 앱을 연 날과 그 이유, 열지 않은 날과 그 이유
2. 다음 날 **남은 과업 다시 배정**으로 계획을 이어 갈 수 있었는지
3. 오늘 계획과 이번 주 예측이 실제 공부 계획에 쓸모가 있었는지, 어떤 점이 달랐는지
4. 앱을 쓰면서 따로 하게 된 일(파일 정리, 시간 계산 등)
5. 스캔 PDF 인식이나 AI 계정 연결이 없어서 불편했던 순간이 있었는지
6. 앱을 계속 쓸지, 제거할지, 제거한다면 기록을 남길지

## 7. 기록과 개인정보

학생의 학습 기록과 PDF 사본은 학생 PC의 `%LOCALAPPDATA%\ChallengeMaster`에만 있다. 앱은 이 자료를 외부로 보내지 않는다. 운영자가 보관하는 것은 관찰 메모와 참여자가 직접 보낸 화면 캡처·오류 로그뿐이다.

관찰 메모에는 참여자 이름 대신 P1·P2·P3를 쓴다. 이 저장소는 공개 저장소다. 관찰 메모, 참여자가 보낸 캡처와 로그는 **저장소 밖**에 두거나, 저장소 안에 둘 경우 `docs/pilot/private/`에만 둔다(`.gitignore`의 `private/`가 이 폴더를 제외한다). 커밋 전에는 변경 파일 목록을 직접 확인한다. 시범 결과는 식별 정보를 뺀 요약만 `docs/`에 남긴다.

## 8. 중단과 종료

다음 중 하나가 생기면 해당 참여자의 시범을 멈추고 원인을 먼저 고친다.

- 설치가 차단되어 보안 설정을 바꾸지 않고는 진행할 수 없을 때
- 학습 기록이나 PDF 사본이 사라지거나 다른 자료와 섞였을 때
- 참여자가 부담을 이유로 중단을 원할 때(이유를 묻지 않는다)

시범은 모든 참여자가 설치·첫 계획·다시 배정·제거 선택을 한 번씩 해 보았거나, 막힌 지점이 기록되었을 때 끝난다. 끝나면 [작업 상태](../status.md)에 결과 요약을 남기고, 서명과 일반 배포 경로, OCR과 계정 연결의 순서를 다시 결정한다.
