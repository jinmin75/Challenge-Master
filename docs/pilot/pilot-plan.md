# 시범 사용 운영 절차 (v0.6)

작성일 `2026-09-27`. 대상은 시범을 운영하는 사람이다. 근거 결정은 [D016~D018](../decisions.md), 설치본 상태는 [v0.6 검증 기록](../verification-v0.6.md)이다. 아래의 인원·시간·관찰 항목은 작업자가 정한 초안이며 확정된 연구 설계가 아니다.

## 1. 목적과 범위

시범의 목적은 학생이 설치부터 첫 계획, 다음 날 복귀, 제거까지 혼자 진행할 때 **어디서 막히는지**를 찾는 것이다. 학습효과, 임용시험 성과, 만족도 점수는 측정하지 않는다. 참여자가 2~3명이라 그런 주장을 뒷받침할 수 없다.

관찰 대상은 설치 과정, PDF 등록과 추출 검토 화면, 오늘 시작과 시간 기록, 다음 날 다시 배정, 제거할 때의 기록 삭제 선택(Windows는 제거 화면의 선택 칸, Mac은 가이드 13절의 수동 삭제)이다. 스캔 PDF 인식(OCR)과 LLM 계정 연결은 v0.6에 없다. 스캔 쪽은 `글자 없음`으로 표시만 한다. 참여자가 이 기능을 찾는지는 관찰해서 다음 구현 순서를 정하는 근거로 쓴다.

## 2. 시작 전 조건

1. **깨끗한 환경 시험 통과.** 운영 PC에서 Windows 샌드박스를 켜고 `npm run test:sandbox`가 `passed: true`로 끝나야 한다. 실패하면 시범을 시작하지 않는다. `2026-09-27` v0.5.0과 v0.6.0 설치파일로 통과했다. 이 시험은 무인 설치이므로 Windows 경고 화면은 확인하지 못한다. Mac 앱은 GitHub의 macOS 환경에서 빌드와 자동 시험(Apple Silicon·Intel)이 통과한 압축파일만 배포한다. 이 자동 시험은 브라우저를 열지 않는 설정으로 돌았으므로, Mac에서 브라우저가 저절로 열리는지는 첫 Mac 참여자에게서 관찰한다.
2. **전달 경로는 구글 드라이브 공유 링크.** 모든 참여자에게 같은 링크를 준다. 링크로 내려받은 파일에는 인터넷에서 받은 파일이라는 표시가 붙어, 드라이브·브라우저·Windows의 경고가 나타날 수 있다(`확인 필요`). 다시 빌드해도 공유 파일이 바뀌지 않도록, 배포할 설치파일은 `dist/`를 직접 공유하지 않고 별도 공유 폴더에 복사해 올린다. Mac 압축파일은 GitHub Actions 결과물(`challenge-master-macos`)로 받는다. `gh run download`나 웹에서 받은 바깥 묶음만 풀고, 안쪽 `Challenge-Master-0.7.0-macos.zip`은 **풀지 않은 채** 올린다. Windows에서 풀었다가 다시 압축하면 실행 권한과 앱 구조가 사라져 실행되지 않을 수 있다. 올린 파일의 SHA-256을 다시 대조한다. GitHub 결과물은 30일 뒤 삭제되므로 받은 즉시 저장소 밖에 보관한다.
3. **운영자 직접 설치.** 2항의 **드라이브 링크로 내려받은** 설치파일을 운영자 PC에서 설치·실행·제거하면서 브라우저 다운로드 경고, Windows 경고 창, 설치 마법사, 제거 화면을 캡처한다. 직접 빌드한 파일을 그대로 실행하면 학생이 보는 경고가 재현되지 않을 수 있다. 제거 화면의 삭제 칸을 시험하기 전에는 운영자 PC에 `%LOCALAPPDATA%\ChallengeMaster`가 없는지 먼저 확인한다. 폴더가 있으면 삭제 칸 시험은 하지 않는다. 운영자에게 Mac이 없으므로 Mac의 경고·허용 화면은 **첫 Mac 참여자의 첫 사용 관찰**에서 캡처한다.
4. **학생 가이드.** 학생에게는 [Windows 가이드](guide/guide-windows.html)와 [Mac 가이드](guide/guide-mac.html)를 PDF로 만든 것을 준다(공유폴더의 `Challenge Master 설치·사용 가이드` 두 파일). 가이드에는 링크를 넣지 않고 「운영자가 보낸 링크」로만 쓴다. 링크는 공개 저장소의 파일에 넣지 않는다. 가이드는 확인하지 못한 두 화면(Windows 파란 경고 창, Mac 첫 경고 창)을 「글자가 설명과 다르면 누르지 말고 캡처」로 처리한다. 3항과 첫 Mac 참여자 관찰에서 실제 화면을 얻으면 그 캡처로 해당 부분을 고친다.
5. **설치파일 확인값.** Windows는 `dist/Challenge-Master-Setup-0.7.0-win-x64.exe.sha256`, Mac은 GitHub에서 받은 `Challenge-Master-0.7.0-macos.zip.sha256`의 값이 [v0.7 검증 기록](../verification-v0.7.md)과 같은지 확인한다. 첫 사용 관찰 때 학생 PC에서 대조한다. Mac은 학생이 zip을 풀기 전에 대조한다. Windows는 PowerShell `Get-FileHash <파일 경로>`, Mac은 터미널 `shasum -a 256 <파일 경로>`로 확인한다.
6. **참여자 기기 조건.** Windows는 Windows 11 x64에서 확인했고, Windows 10·ARM PC·S 모드 PC는 확인하지 않았다. Mac은 macOS 13.5 이상이어야 한다. 이 하한은 포함한 Node.js 24의 지원 범위(Node.js BUILDING.md)를 따른 것이며, 자동 시험을 돌린 macOS는 15와 26뿐이며 13.5~14는 시험하지 않았다. 실제 Mac 기기에서 학생이 쓰는 모습도 아직 관찰하지 않았다.

## 3. 보안 설정 확인

### 3.1 Windows: 스마트 앱 컨트롤

Microsoft 지원 문서에 따르면, 스마트 앱 컨트롤은 서명되지 않았거나 서명이 잘못된 앱을 신뢰할 수 없는 앱으로 보고 차단한다. 문서는 개별 앱에 예외를 줄 방법이 현재 없다고 밝힌다(`2026-09-27` 확인, [스마트 앱 컨트롤 FAQ](https://support.microsoft.com/ko-kr/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)). v0.6 설치파일과 제거 프로그램은 서명되지 않았다.

이 확인은 드라이브 링크를 보내기 **전에** 한다. 상태 이름과 동작은 위 문서에 나오지 않으므로 아래 구분은 `확인 필요`다.

- **꺼짐:** 참여 가능하다.
- **켜짐 또는 평가:** 설치가 막힐 수 있다. 참여자에게 이 기능을 끄라고 요구하지 않으며, 서명판이 나올 때까지 해당 참여자는 제외하는 것을 기본으로 한다.

같은 문서는 최근 Windows 업데이트부터 클린 설치 없이 Windows 보안 앱에서 이 기능을 다시 켤 수 있다고 밝힌다. 참여자가 스스로 이 기능을 다시 켜려 한다면 서명 없는 제거 프로그램이 막힐 수 있으므로(`확인 필요`) 먼저 앱을 제거하도록 안내한다. 마무리 면담 때 설정 상태를 한 번 더 적는다.

### 3.2 Mac: 처음 한 번 허용

Mac 앱도 Apple 개발자 서명과 공증이 없다. Apple 지원 문서에 따르면, 이런 앱은 처음 열 때 막히고 사용자가 `시스템 설정` → `개인정보 보호 및 보안`에서 `그래도 열기`를 눌러야 한다(`2026-09-27` 확인, [Apple 지원 102445](https://support.apple.com/en-us/102445)). 이 단계는 참여 조건이 아니라 설치 절차의 일부이며, 한국어 메뉴 이름은 첫 Mac 참여자의 화면으로 확인한다. GitHub 시험 환경에서 이 앱에 대한 Gatekeeper 판정도 기록했다([v0.6 검증 기록](../verification-v0.6.md)). 다만 그 환경의 파일에는 인터넷에서 받았다는 표시가 없으므로 학생 화면과 같다고 보지 않는다.

이 앱 하나에 대해 `그래도 열기`를 누르는 것은 8절의 「보안 설정 변경」으로 보지 않는다. `그래도 열기` 단추가 없거나 학교·기관 관리 기기라서 막히면, 터미널 명령이나 Gatekeeper 설정 변경을 안내하지 않고 해당 참여자를 제외한다.

## 4. 진행 순서 (제안값)

| 단계 | 시점 | 방식 | 운영자가 할 일 |
|---|---|---|---|
| 사전 확인 | 1일차 전 | 대면 또는 메신저 | 목적 설명, Windows는 스마트 앱 컨트롤 확인(3.1절)·Mac은 macOS 버전 확인, 드라이브 링크와 해당 운영체제의 학생 안내 전달 |
| 첫 사용 관찰 | 1일차, 30~40분 | 대면 또는 화면 공유(녹화하지 않음) | 설치파일 확인값 대조 후 설치 안내만 주고 지켜본다. 참여자가 도움을 청하기 전에는 개입하지 않는다 |
| 혼자 사용 | 2~7일차 | 참여자 단독 | 사용 빈도는 요청하지 않는다. 운영자는 연락을 기다린다 |
| 마무리 면담 | 7일차 전후, 20~30분 | 대면 또는 화면 공유(녹화하지 않음) | 면담 질문(6절), 제거 여부와 기록 삭제 선택을 참여자가 정한다 |

첫 Mac 참여자는 예외로 운영자가 화면을 함께 보며 진행한다(2절 4항). 이 참여자의 관찰 메모에는 `동반`이라고 표시해, 혼자 진행한 참여자의 기록과 구분한다.

첫 사용에 쓸 PDF는 참여자가 이용 권한을 가진 자료로 한다. 운영자가 교재 파일을 나눠 주지 않는다. 텍스트를 선택할 수 있는 PDF에서만 추출이 된다는 점과 32MB·30쪽 제한을 미리 알린다.

## 5. 관찰 기록 항목

첫 사용 관찰에서는 아래를 시간과 함께 적는다. 참여자의 PDF 내용, 답안, 화면에 보이는 교재 원문은 적지 않는다.

- 설치파일 실행부터 첫 화면이 열릴 때까지 걸린 시간, 경고가 떴는지, 참여자가 어떻게 통과했는지
- **공부 범위** 칸을 설치 안내와 화면 도움말만으로 채웠는지
- **이 설정으로 시작** 다음에 **오늘 시작**을 스스로 찾았는지
- **PDF 추출 검토**의 `원본 대조 필요` 표시를 어떻게 이해했는지. 이 화면은 쪽 번호와 상태만 보여 준다. 글자가 없는 쪽은 `글자 없음(스캔 또는 빈 쪽)`으로 표시하며, v0.6 이전에 등록한 자료만 기존처럼 `추출 초안`으로 보인다. 실제 추출 여부는 참여자가 허락하면 기록 폴더의 추출 초안 파일에서 확인한다
- 도움을 요청한 지점과 요청 내용, 운영자가 개입한 지점
- 오류 메시지 원문. 앱이 열리지 않으면 Windows는 `%LOCALAPPDATA%\ChallengeMaster\startup-error.log`, Mac은 `~/Library/Application Support/ChallengeMaster/startup-error.log`와 `~/Library/Logs/ChallengeMaster/launcher.log`가 생겼는지
- Mac: 첫 경고창에서 누른 단추, `그래도 열기`를 찾아간 경로, 허용 뒤 브라우저가 저절로 열렸는지와 걸린 시간, 추가로 뜬 시스템 창(있으면 원문)

## 6. 마무리 면담 질문

1. 첫날 이후 앱을 연 날과 그 이유, 열지 않은 날과 그 이유
2. 다음 날 **남은 과업 다시 배정**으로 계획을 이어 갈 수 있었는지
3. 오늘 계획과 이번 주 예측이 실제 공부 계획에 쓸모가 있었는지, 어떤 점이 달랐는지
4. 앱을 쓰면서 따로 하게 된 일(파일 정리, 시간 계산 등)
5. 스캔 PDF 인식이나 AI 계정 연결이 없어서 불편했던 순간이 있었는지
6. 앱을 계속 쓸지, 제거할지, 제거한다면 기록을 남길지

## 7. 기록과 개인정보

학생의 학습 기록과 PDF 사본은 학생 기기에만 있다. Windows는 `%LOCALAPPDATA%\ChallengeMaster`, Mac은 `~/Library/Application Support/ChallengeMaster`이며, Mac은 실행 기록을 `~/Library/Logs/ChallengeMaster`에도 남긴다. 앱은 이 자료를 외부로 보내지 않는다. 운영자가 보관하는 것은 관찰 메모와 참여자가 직접 보낸 화면 캡처·오류 로그뿐이다.

관찰 메모에는 참여자 이름 대신 P1·P2·P3를 쓴다. 이 저장소는 공개 저장소다. 관찰 메모, 참여자가 보낸 캡처와 로그는 **저장소 밖**에 두거나, 저장소 안에 둘 경우 `docs/pilot/private/`에만 둔다(`.gitignore`의 `private/`가 이 폴더를 제외한다). 커밋 전에는 변경 파일 목록을 직접 확인한다. 시범 결과는 식별 정보를 뺀 요약만 `docs/`에 남긴다.

## 8. 중단과 종료

다음 중 하나가 생기면 해당 참여자의 시범을 멈추고 원인을 먼저 고친다.

- 설치가 차단되어 보안 설정을 바꾸지 않고는 진행할 수 없을 때
- 학습 기록이나 PDF 사본이 사라지거나 다른 자료와 섞였을 때
- 참여자가 부담을 이유로 중단을 원할 때(이유를 묻지 않는다)

시범은 모든 참여자가 설치·첫 계획·다시 배정·제거 선택을 한 번씩 해 보았거나, 막힌 지점이 기록되었을 때 끝난다. 끝나면 [작업 상태](../status.md)에 결과 요약을 남기고, 서명과 일반 배포 경로, OCR과 계정 연결의 순서를 다시 결정한다.
