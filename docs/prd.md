# 한국교원대학교 임용 수험생 개인 학습 가이드 — v4.2

2026-09-23. 현재 설계 정본. 사용자 의견에 따라 초기 기획의 상용 플랫폼·상시 전문가 검토 전제를 대체한다. 로컬 학습 도구의 구현과 제품 전체 완성은 [작업 상태](status.md)에서 구분한다. 학생 계정 실행과 학습효과는 아직 검증하지 않았다.

연결: [검증 명세](test-spec.md), [결정 기록](decisions.md), [향후 서비스 확장](expansion-backlog.md).

## 1. 목표와 범위

한국교원대학교 학생이 자신의 LLM 계정과 보유 학습자료를 이용하여 중등교사 임용시험 준비를 지속하고, 실제 시험 조건에서 필요한 답안을 작성하도록 돕는다. 기관용 자료 유통 플랫폼과 다른 공적 시험 확장은 이번 범위에서 제외한다.

- 학생의 지원 교과·지역·시험연도·전형단계를 기준으로 목표를 설정한다. 대학 소재지로 지원 지역을 추정하지 않는다.
- 실제 합격은 최종 결과다. 학습 중에는 전체 요구 범위, 지연 수행, 제한시간 답안, 반복 오류와 남은 시간을 근거로 다음 행동을 정한다.
- 1차의 연결된 한 단원으로 첫 흐름을 검증한다. 수업실연·면접 등 해당 학생의 나머지 전형 준비는 일정과 준비 항목으로 남기며, 지원하지 않는 수행을 평가 완료로 만들지 않는다.
- 실측 데이터 부재는 현 단계의 출발 조건이다. 기능 구현이나 소규모 사용 관찰을 대규모 효능 연구 완료까지 막지 않는다. 합격률·효과 우월성을 주장하려면 그 주장에 맞는 별도 증거가 필요하다.

## 2. 학생 계정 기반 운영

일상 설명·학습 방향·답안 피드백·오류 확인을 LLM이 맡는다. 건별 유급 전문가 검토를 기본 의존성에서 제거한다. 초기 기획의 사람 검토 비용 예시는 현재 기본 비용으로 적용하지 않는다.

세 가지 경로를 구분한다.

| 경로 | 범위 | 현재 판단 |
|---|---|---|
| 학생이 공식 LLM 앱에서 직접 학습 | 해당 앱이 제공하는 파일·대화·도구 기능 | 가능 범위는 앱·요금제별 확인; 앱 밖 기록을 자동 수집한다고 약속하지 않음 |
| 학생 PC의 공식 계정 인증 도구와 개인 Wiki 연결 | 지원된 로컬 연결로 필요한 자료만 읽고 학습 상태 저장 | 우선 검증할 경로; 실제 계정·연동 시험 필요 |
| 별도 서버가 모든 학생의 구독을 대신 호출 | 중앙 운영·무인 호출·계정 토큰 보관 | 이번 설계에서 제외; 학생 구독을 범용 API 이용권으로 취급하지 않음 |

공통 계약:

- 인증은 공식 로그인 화면과 도구가 관리한다. 서비스·교수자는 학생 비밀번호·인증 쿠키·토큰을 수집하지 않는다.
- 사용량 한도에 도달하면 저장과 로컬 계획은 유지하고 모델 작업만 대기한다. 유료 API·추가 크레딧·다른 계정으로 자동 전환하지 않는다.
- 자동화가 지원되는 경로만 자동이라고 표시한다. 앱을 닫았거나 PC가 꺼져 실행되지 않은 작업을 모니터링 완료로 기록하지 않는다.
- 최초 지원 경로는 학생이 실제로 사용할 계정·기기 조합 한 개부터 검증한다. 여러 LLM 간 동일 기능·성능을 가정하지 않는다.
- 학생 구독료, 장치·OCR·저장 비용, 설치·지원·유지보수 시간은 남을 수 있다. 상시 채점 인건비를 제거한 것과 전체 비용 0원은 구별한다.

## 3. LLM 전문가 역할의 실행 계약

역할 프롬프트에 '최고 전문가'라고 쓰는 것으로 정확도를 보증하지 않는다. 다음 작업을 구조화한다.

1. 학생이 지정한 범위와 확인된 시험 요구를 대조해 필요한 수행을 나눈다.
2. 개인 Wiki에서 판본·쪽수·근거를 찾는다. 추출되지 않은 페이지를 읽었다고 말하지 않는다.
3. 설명과 과제를 제시하고, 학생의 실제 답안과 도움 사용을 기록한다.
4. 답안의 충족 요소·누락·오류 후보를 근거와 연결한다. 공식 기준, 교재 해설, AI 추정을 표시한다.
5. 해설을 외운 즉시 수정과 지연 재수행을 분리해 다음 과제를 정한다.

LLM은 교수자·공식 채점자를 사칭하지 않는다. 근거 충돌·추출 오류·모호한 해설은 '확인 필요'로 남기며 해당 내용의 단정적 채점과 숙달 갱신을 중지한다. 학생이 요청하면 원문 비교와 문의용 질문을 만들 수 있지만, 사람의 응답이나 유료 검토 대기열을 기본 서비스로 약속하지 않는다.

모델의 재검토나 역할 분리는 오류를 찾는 수단이다. 같은 모델의 동의를 독립 전문가 검증으로 세지 않는다. 모든 답안에 여러 모델을 호출하지 않고 불확실한 부분만 추가 검토한다.

## 4. 개인 교재 Wiki 반입

학생이 합법적으로 이용할 수 있는 개인 자료를 지정하면 반입을 시작하는 흐름으로 바꾼다. 기관이 먼저 공통 교재팩을 확보해야만 시작할 수 있다는 전제는 제거한다.

- 원본은 개인 저장공간에 보존한다. 사용자의 삭제 요청·보존기간 정책은 별도로 적용한다.
- 파일별 제목·판본·장/절·페이지·추출 범위·해시·추출 상태를 남긴다. 원문, 검색용 추출본, AI 설명, 학생 답안은 구분한다.
- OCR 누락, 표·수식 파손, 페이지 순서 오류는 자동 검출과 표본 확인 대상으로 둔다. 문제가 있는 구간은 피드백 근거에서 제외한다.
- 한 번 파일을 지정하면 추출·색인·연결은 가능한 범위에서 이어서 수행한다. 매 페이지 승인·수동 Wiki 편집을 학생에게 요구하지 않는다. 중단 후 재개·중복 반입 방지를 검증한다.
- 개인 로컬 이용, 클라우드 처리, 공동 Wiki 공유, GitHub 공개는 별개의 허용 범위다. 로컬 저장이 허용됐다는 이유로 외부 모델 전송까지 켜지 않는다.
- 이용 근거는 자기 저작, 이용 허락, 적용 가능한 법정 예외 등으로 구분한다. 출판사 계약만을 유일한 근거로 요구하지도, 책 구매만으로 모든 처리를 허용하지도 않는다.
- 전송 범위가 미확인인 자료는 외부 전송하지 않는다. 책의 위치 안내와 학생의 직접 학습은 계속할 수 있지만 원문 기반 AI 분석이 된 것처럼 표시하지 않는다. OCR도 외부 서비스 이용이면 같은 전송 검사를 적용한다.
- 공식 LLM 앱에 학생이 직접 올리는 것도 외부 전송이다. 연결 도구는 최초 전송 전에 대상 제공자·자료·이용 목적·전송 범위를 보여 주고 명시적 동의를 받는다. `consent_id, provider, source_ids, allowed_operations, granted_at, revoked_at, policy_version`을 보존한다. 자동 전송마다 이 동의와 자료 이용 범위를 검사한다. 권리 확인과 학생 동의는 서로 대체하지 않는다.
- 앱 밖 직접 업로드는 시스템이 관측했다고 주장하지 않는다. 학생이 보고한 경우에만 `self_reported_external_upload`로 구분한다. 동의 철회는 이후 자동 전송과 대기 작업을 막는다. 이미 제공자에게 보낸 자료의 삭제는 제공자 기능·정책에 따라 별도 확인하며 즉시 회수됐다고 표시하지 않는다.
- 반입된 원문·답안·개인정보는 학생 간 공동 저장소나 GitHub에 자동으로 올리지 않는다.

### 4.1 PDF → 충실 변환 MD → 검증 → Wiki

PDF는 원본을 보존하고, 검색·인용에 사용할 Markdown(MD) 추출본을 만든 뒤 Wiki에 반입한다. 학생이 PDF와 학습 범위를 지정하면 중간 과정은 시스템이 처리한다. MD 파일을 직접 만들거나 페이지마다 승인하는 과정을 학생에게 요구하지 않는다.

1. **접수와 처리 경로 결정:** 원본 해시, 파일명, 판본, 전체 페이지 수와 선택 범위를 기록한다. 텍스트 PDF는 추출을 우선하고, 스캔·혼합 페이지는 OCR 또는 이미지 판독을 사용한다. LLM은 필요한 구조 복원과 정규화에 참여한다. 모든 페이지를 무조건 LLM으로 다시 쓰지 않는다. 외부 OCR·LLM 호출에는 4절의 자료 이용 범위와 전송 동의를 적용한다.
2. **충실 변환본 작성:** 제목, 본문 순서, 문제 번호, 보기, 해설, 표·수식·각주를 보존한다. PDF 파일 페이지 번호와 책에 인쇄된 쪽수는 별도 필드로 기록하며 쪽수가 없거나 판독되지 않으면 미확인으로 둔다. 각 블록에 `source_id, source_hash, conversion_version, pdf_page_index, printed_page_label, block_id`를 연결한다. PDF 페이지 인덱스는 1부터 시작한다.
3. **이미지·불확실 구간 처리:** 도표·수식을 정확히 텍스트화하지 못하면 원본 페이지/영역 참조와 오류 상태를 남긴다. 원문에 없는 내용을 보충하거나 빈 부분을 추측해 채우지 않는다. 이미지가 학습에 필수인데 확인되지 않았다면 그 구간은 준비 완료가 아니다.
4. **검증과 부분 준비:** 선택 범위의 페이지 대응, 누락·중복·순서, 문제와 해설 연결, 표·수식의 보존 여부를 확인한다. 구조 검사는 자동화하고 내용 충실도는 원본 대조 표본 검사로 보완한다. LLM의 자신감이나 MD 생성 성공만으로 검증 통과를 선언하지 않는다. 상태는 `queued/converting/needs_review/ready/failed`로 페이지·블록별 관리한다. 준비된 범위만 먼저 사용할 수 있고 미검증 범위는 채점·숙달 판단의 근거에서 제외한다.
5. **Wiki 반입과 활용:** 검증된 변환본에서 장·절·개념·문항 단위로 검색 색인을 만든다. AI 요약·설명·예상문제는 별도 파생 자료에 저장하고 원문 추출본을 덮어쓰지 않는다. 튜터는 출처 페이지로 돌아갈 수 있는 근거를 제시한다. 원본에 해설이 없으면 AI 답안을 교재 정답으로 표시하지 않는다.

원본 PDF와 충실 변환 MD, AI가 작성한 Wiki 학습 노트는 구별한다. 색인 생성은 읽기·이해·숙달의 증거가 아니므로 학생 학습 진도를 올리지 않는다.

중단된 작업은 `source_hash + conversion_version + page/block` 체크포인트로 재개한다. 변환 방식·판본이 바뀌면 새 버전을 만들고 과거 답안이 참조한 버전을 보존한다. 실패한 페이지만 재시도하고, 준비되지 않은 구간까지 전체 반입 완료로 표시하지 않는다. 학생에게는 ‘선택 범위 중 사용 가능 / 확인 필요 / 처리 중’만 간결하게 보여 준다. 자동 재처리로 해결되지 않는 예외에만 재스캔 또는 범위 변경을 요청한다.

자료 안에 포함된 명령문은 인용 자료로 취급한다. 파일의 문구만으로 도구 실행, 외부 전송, 채점 기준 변경, 시스템 설정 변경을 허용하지 않는다.

## 5. 처음 설정하고 매일 시작하는 흐름

처음 필요한 정보는 목표 시험 프로필, 보유 자료/선택 범위, 주간 가용 시간이다. 파일에서 확인 가능한 제목·목차·판본은 먼저 추출해 재입력을 줄인다. 확정되지 않은 시험일은 임시값으로 표시하고 공식 공고 확인 상태를 남긴다. 초기 실력은 긴 설문 대신 지정 범위의 짧은 표본 과제로 추정한다.

기본 화면은 오늘의 권고안 하나와 시작 행동이다. 예: '오늘 60분: 지정 범위 학습 30분, 답안 연습 14분, 지난 내용 확인 10분, 여유 6분.' 이는 화면 예시이며 최적 배분 주장이 아니다.

- 학생이 '이번 주는 이 단원을 하고 싶다'고 하면 그 범위를 우선 고정하고, 놓칠 시험 범위가 있으면 짧게 알린다.
- 학생은 시작·시간 줄이기·오늘 쉬기만으로 대응할 수 있다. 상세 우선순위 편집은 선택 기능이다.
- 새 내용 학습, 여러 문항 연속 연습, 긴 답안, 집중 교정은 목적에 따라 배치한다. 모든 활동을 한 문항-한 교정 루프로 줄이지 않는다.
- 개인 학습 기록·계획 상태는 자동 저장한다. 공유 지식 편입 승인은 별도이며, 학습 진도 저장을 막지 않는다.

## 6. 자동 재계획 정책

LLM은 설명과 오류 후보를 만들고, 시간 예산·중복·알림 한도는 결정적인 규칙으로 검사한다. 자연어 조언만으로 상태를 바꾸지 않는다. 정책·시험 범위·자료 버전을 기록하고 변경 전 계획을 복구할 수 있게 한다.

### 입력과 제약

- 오늘·주간 가용 시간, 휴식일, 시험 일정, 현재 선택 범위.
- 과업의 개념·범위·예상 시간·선행 관계·최근 시도·도움·오류 근거.
- 외부 공부 자기보고와 실제 평가 결과의 구분.
- 계정 한도·네트워크·자료 준비 상태. 기술 장애를 학생 결석·실력 저하로 세지 않는다.

### 배정 순서와 과부하 처리

1. 휴식·시간 상한·자료 및 계정 제약을 먼저 적용한다. 가용 시간을 T, 초기 여유를 0.1T, 배정 가능 시간을 B=0.9T로 둔다. 아래 60:40과 신규 최소 40%의 분모는 모두 B다. T=60분이면 B=54분이다. 정수 분 단위에서는 신규 보호 시간은 올림하고 나머지를 복습에 배정해 총량이 B를 넘지 않게 한다.
2. 선택 범위의 다음 과업을 막는 확인된 선행 오류, 오늘 기한인 미확인/복습, 아직 다루지 않은 선택 범위를 순서대로 검토한다. 불확실한 오류는 진단 과제로 처리하며 확정 오개념으로 누적하지 않는다.
3. 새 범위 시간과 확인·교정 시간을 별도 예약한다. 초기 가정은 배정 가능 시간의 60:40이다. 최적값이 아니며 정책 버전으로 관리한다.
4. 복습이 앞으로 이틀의 복습 예산보다 많으면 같은 개념의 중복 요청을 하나의 확인 과제로 합칠 수 있다. 원 답안과 다른 오류는 보존한다. 같은 단어만으로 서로 다른 오류를 합치지 않는다.
5. 초과 시 다음 세션의 확인·교정 몫을 최대 B의 60%로 조정하고 새 범위는 최소 B의 40%를 남긴다. 확인된 선행 오류가 현재 범위를 막으면 다른 학습 가능한 범위를 추천한다. 모든 범위가 막히면 이 비율보다 선행 학습을 우선하고 예외 사유를 기록한다. 긴 통합 답안을 쪼개야만 비율을 맞출 수 있으면 과업의 의미 있는 경계를 우선하고 해당 세션의 예외와 주간 보정안을 남긴다. 새 진도 비율을 허위로 채우지 않는다.
6. 남은 과업은 기한·선행 의존·원래 예정일 순으로 재배치한다. 이미 충분히 확인한 내용의 추가 반복을 먼저 늦추되, 미확인 범위를 숙달로 만들거나 사라지게 하지 않는다.
7. 총량이 시험 전 시간에 들어가지 않으면 가용 시간 안에서 가능한 기본안을 먼저 제시하고 빠진 범위를 표시한다. 약속된 학습시간 증액·목표 범위 제외는 학생 동의 없이 하지 않는다. 응답이 없으면 기존 시간·범위를 유지한 다음 과업으로 진행한다. 첫 화면에 '임시 진행안 · 현재 시간으로 전체 범위 완료 어려움'을 계속 표시하고 목표·미배정 범위를 유지한다. 알림을 반복하지 않고 상태 표시로 남긴다.

위 비율과 이틀 기준은 조정할 초기값이다. 시험 결과를 개선한다는 경험적 근거로 인용하지 않는다.

### 관측·상태 계약

- 일정: `plan_version, task_id, time_budget_minutes, allocatable_minutes, assigned_minutes, schedule_exception_reason, goal_coverage_status`.
- 알림: `notification_id, scheduled_at, attempted_at, delivery_status(unknown/sent/confirmed/failed), opened_at, consent_id`. 전송 성공과 학생 열람은 다르다. 제공자가 확인하지 못하는 값은 unknown이다.
- 학습: `attempt_id, evidence_type(observed_attempt/self_reported_reading/self_reported_external_upload/unobserved), assistance_exposure, source_version, rubric_basis`.
- 미수행: `learner_confirmed_noncompletion, confirmation_at, planned_rest`. 알림 미응답으로 이 필드를 true로 바꾸지 않는다.
- 실행: `runner_last_seen_at, model_job_status, account_limit_status(unknown/available/limited), connectivity_status`. 마지막 관측 이후 장치 전원·외부 앱 사용을 추정해 사실로 저장하지 않는다.
- 상태 갱신은 과업·계획 버전과 이벤트 id로 중복을 막는다. 개인정보 최소 수집·보존·내보내기·삭제 원칙을 적용한다.
- 기록에서 다음 계획의 잔여 분량을 자동 차감할 때는 현재 계획에 배정된 과업에서 학생이 완료를 명시적으로 확인한 분량만 사용한다. 재계획 입력의 임의 완료 과업 목록으로 이 기록을 우회하지 않는다. 자기보고 읽기·알림 미응답·미수행 확인을 완료로 바꾸지 않는다. 완료 분량과 개념 숙달은 별개로 기록한다. 계획이 바뀐 뒤 도착한 이전 계획의 완료 기록은 현재 잔여 분량을 고치지 않는다.

### 결손·복귀의 기본 조치

| 관측한 상황 | 기본 조치 | 금지 |
|---|---|---|
| 예약 시각에 반응 없음 | 허용 시간대에 알림 1회; 다음 접속 시 짧은 시작 과제 | 공부 안 했다고 확정, 실력 감점 |
| 학습자가 하루 미수행을 확인 | 미완료 과업을 현재 예산 안에서 재배치 | 다음 날 분량 두 배 |
| 미수행이 반복됨 | 최소 시작 과업과 줄인 당일 권고안; 주간 완료 예상 갱신 | 목표를 몰래 낮춤, 밀린 과제를 삭제 |
| 종이책 공부를 했다고 보고 | 범위 기록 후 다음 세션에서 표본 확인; 중복 읽기 자동 부과 보류 | 자기보고만으로 숙달 확정 |
| 응답·학습 증거가 계속 없음 | 상태를 미확인으로 남기고 다음 허용 세션까지 대기 | 알림 수를 계속 늘림, 교수자에게 무단 보고 |

## 7. 적극적 개입과 압박의 경계

학생이 동의한 시간·강도 안에서 약속 이행을 요구한다. 앱 안의 기본 권고는 '적극적 가이드'다. 백그라운드 재촉은 기본 꺼짐이며 온보딩에서 실제 예시 문구와 횟수를 보여 준 뒤 학생이 켠다. 강도·휴식·알림 시간은 학생이 언제든 바꿀 수 있다. 재촉 동의 없이도 앱 안의 안내와 학습 기능을 사용할 수 있다.

- 시작 시 오늘 해야 할 범위와 미루면 밀릴 구간을 구체적으로 제시한다. 합격 실패를 단정하거나 죄책감을 유도하지 않는다.
- 학습 중에는 의미 있는 범위 경계에서 짧은 회상·답안 확인을 넣는다. 학생이 정답을 보기 전 시도할 기회를 제공한다.
- 같은 오류가 새 과제에서도 확인되면 설명·예시·재시도 과업을 먼저 제안한다. 관련 없는 다음 공부나 종료를 잠그지 않는다.
- 알림은 초기 기본값으로 세션 전 1회, 무응답 후 재촉 1회, 하루 최대 2회다. 미응답으로 무한 증가하지 않는다. 조용한 시간과 휴식 요청이 우선한다.
- 알림 차단·전원 꺼짐·계정 한도 상황에서는 전달하지 못했다고 표시한다. 앱이 열려 있을 때의 개입과 백그라운드 알림을 구별한다.
- 교수자 공유는 별도 선택이다. 동의하지 않아도 개인 학습 기능을 사용할 수 있다. 원문·오답·휴식 기록을 자동 공유하지 않는다.

## 8. 합격 목표를 일상 판단에 연결하는 기준

시험 준비가 얼마나 진행됐는지 하나의 임의 백분율로 합치지 않는다. 다음 증거를 전체 시험 요구와 연결한다.

- 범위: 학습 예정 / 자기보고 학습 / 실제 확인 / 아직 미확인.
- 수행: 처음 보는 관련 과제에 핵심 요소를 도움 없이 구성하는지.
- 안정성: 시점을 달리한 과제에서도 수행이 유지되는지, 같은 오류가 반복되는지.
- 시간: 해당 시험의 확인된 제한시간과 답안 형식을 충족하는지.
- 단계: 1차와 해당 지역·교과의 후속 전형 준비가 각각 어디까지 진행됐는지.

준비도는 위 증거의 설명이지 합격확률이 아니다. 공식 채점 기준이 없으면 교재/연습 기준을 명시하고 공식 점수로 부르지 않는다. 관측된 취약점 중 다음 시험 수행을 가장 막는 부분을 오늘 권고에 반영한다. 가이드의 사용 횟수나 답안 개수 자체를 최종 목표로 삼지 않는다.

## 9. 구현 순서와 기존 자산의 경계

1. 개인 계정 연결 시험: 실제 계정·기기 한 조합에서 공식 지원 경로를 확인한다. 학생 토큰은 읽거나 수집하지 않는다. 계정 제품의 지원 범위·이용 조건은 구현 시점의 공식 문서에서 다시 확인한다.
2. 교재 범위 반입: 4.1절에 따라 합성 PDF에서 충실 변환 MD와 출처 페이지 연결을 검증한다. 단순 출처 노트 작성과 실제 OCR·내용 분석을 구별한다.
3. 순수 스케줄 정책과 저장: 네트워크·LLM 없이 가상 일정 테스트를 통과시킨다. 복습일 목록 표시와 자동 재계획을 구별한다.
4. 계정 기반 튜터와 학습 상태 연결: LLM 출력의 출처·필드·허용 범위를 검사한 뒤 계획 변경을 반영한다. 지연 응답이 새 계획을 덮어쓰지 않게 한다.
5. 시작·연속 학습·중단·복귀·휴식·재촉 UX를 합성 자료로 검증한다. 학생 자료 처리와 파일럿 참여는 각자의 권한·동의 범위 안에서 시작한다.

기존 대시보드·Wiki 시연은 별도 자산이다. 이 저장소에 기존 실행 코드가 이관되었다고 가정하지 않는다. 시연의 모델 호출 차단과 로컬 대체 동작을 해제하는 것으로 운영 연동 검증을 대신하지 않는다. 현재 새로 구현한 로컬 코어와 기존 앱·실제 계정 연동의 실행 상태를 구분한다.

### 9.1 설치파일 배포 계약

학생에게는 Windows 설치파일을 제공한다. 설치 후 Node.js·Python을 학생이 따로 설치하거나 명령줄에서 설정해야 하는 상태를 배포 완료로 보지 않는다. PDF 추출에 필요한 실행 환경과 패키지는 설치파일에 포함하고, 설치·업데이트·제거 과정에서 원본 PDF를 바꾸지 않는다. 학습 기록은 설치 폴더와 분리된 사용자 전용 위치에 둔다. 제거 시 개인 기록을 지울지 여부는 학생이 선택해야 한다.

설치파일은 깨끗한 Windows 환경에서 설치·첫 실행·PDF 반입·기록 후 재시작·주간 재계획·제거를 검증한다. 현재 개발용 Python 패키지를 사용하는 로컬 PDF 어댑터를 설치파일 완성으로 간주하지 않는다. 배포본의 라이선스 고지, 실행 파일 서명과 업데이트 경로는 빌드 시 확인한다.

## 10. 범위 종료 기준

이번 설계의 완료는 [검증 명세](test-spec.md)의 입력·예외·관측 근거가 구체화됐다는 뜻이다. 구현 완료는 실제 테스트, 현장 적합성은 학생 사용 관찰로 따로 판정한다. 대규모 효능 연구는 효과 주장 단계에 적용하며 현재 기능 개발의 선행 조건으로 삼지 않는다.

다른 공적 시험, 상용화, 기관용 공유팩, QTI 전면 호환, 멀티테넌트 플랫폼은 [확장 보류 문서](expansion-backlog.md)로 옮긴다. 현재 학생용 설계에 불필요한 선택과 기능을 추가하지 않는다.
