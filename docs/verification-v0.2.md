# 로컬 코어 v0.2 검증 기록

2026-09-23. Windows / Node.js 25.6.1. 입력은 합성 과업과 이벤트만 사용했다. 학생 자료, 실제 PDF, 외부 계정·모델은 사용하지 않았다.

| 실행 | 결과 | 확인한 범위 |
|---|---|---|
| `npm test` | 45개 통과, 실패 0 | 기존 32개와 완료 분량·재계획·별도 프로세스 CLI 검사 13개 |
| `npm run check` | 12개 JavaScript 모듈 통과 | 구문과 줄 끝 공백; 전체 정적 분석은 아님 |

현재 계획의 배정량을 넘는 완료 기록, 같은 이벤트 중복 입력, 지난 계획의 늦은 완료 기록을 막았다. 새 계획은 저장 잠금 안에서 최신 이벤트를 읽고 생성한다. 과업이 처음 등장한 계획에서 원래 예상 분량을 복원해 다음 입력과 대조한다. 이미 줄인 분량을 다시 넣거나 과거 과업을 다음 입력에서 빼면 계획을 저장하지 않고 오류를 반환한다. `replan` 입력의 임의 `completedTaskIds`와 `record` 명령의 직접 `plan_created` 이벤트도 거부한다. 저장형 첫 `plan`에서 근거가 사라지는 `completedTaskIds` 입력을 받지 않고, 이후 모든 계획은 `replan`으로만 생성한다. 부분 완료, 전부 완료 뒤 선행 과업 해제, 읽기 자기보고의 분량 유지, 재시작 후 저장·복원을 합성 자료로 확인했다.

이 완료 분량은 학생이 과업을 끝냈다고 확인한 작업량이다. 개념 숙달이나 답안의 질을 뜻하지 않는다. 주간 일정, 실제 학생 화면, PDF 판독, 계정 연결, 알림, 학습효과는 이번 검증 범위 밖이다. [v0.1 기록](verification-v0.1.md)의 PDF 결과 계약 검증도 실제 PDF 변환으로 세지 않는다.
