# 로컬 코어 v0.1 검증 기록

2026-09-22. Windows / Node.js 25.6.1. 입력은 합성 자료만 사용했다. 외부 모델·계정·학생 자료를 사용하지 않았다.

## 실행 결과

| 명령/검사 | 결과 | 범위 |
|---|---|---|
| npm test | 32개 통과, 실패 0 | 일정15, 반입6, 이벤트·저장8, CLI3 |
| npm run check | 10개 모듈 통과 | JavaScript 구문·뒤쪽 공백 검사; ESLint/정적 타입 검사는 아님 |
| node --test --experimental-test-coverage | 32개 통과 | 실행 계측상 줄97.65%, 분기85.48%, 함수100%; 교육적 정확도 수치가 아님 |
| npm run demo | 정상 종료 | 합성 과업 T60/B54, 신규22·복습32; 남은 분량 유지; 자료 2쪽 중 1쪽만 준비됨 표시 |
| 독립 JavaScript 검토 | 수정 후 PASS | 지적한 차단 결함 해소, 32개 테스트 및 기존 실패 입력 재확인 |
| 공개 범위 검사 | 차단 사항 없음 | 합성 자료 확인, 비밀값·개인 장치 경로 검사; 검토 범위 밖 유출까지 보증하지 않음 |

CLI 테스트는 새 Node 프로세스에서 계획 저장→자기보고 기록→동일 이벤트 재입력→상태 복원→계획 버전 증가를 검사했다. 잘못된 JSON은 기존 저장 파일을 바꾸지 않는다. 잠금 경합·손상 파일을 빈 기록으로 초기화하지 않는 것도 확인했다.

스케줄 테스트 하나는 180개 가용 시간·과업 조합을 순회하여 배정 상한, 미배정 분량 보존과 입력 비변경을 검사한다. 이는 180명의 사용자 시험이나 180개의 독립 제품 시나리오를 뜻하지 않는다.

## 결함 재현과 수정

- 이전 계획 피드백이 새 계획에서도 적용 가능으로 남음: 역순 이벤트 회귀 테스트를 먼저 실패시킨 뒤 새 계획 생성 시 stale_plan으로 갱신.
- 분할 불가 복습을 여러 개 배정하면 신규 시간을 침범함: 정상·과부하 경로 모두 누적 복습 예산을 검사하여 신규 보호 시간 유지.
- 전체 과업이 오늘 예산보다 크다는 이유만으로 복습 과부하 정책을 발동함: 복습 부채와 향후 이틀 복습 예산의 비교로 좁힘.
- 직렬화된 자료 상태에서 다른 페이지의 결과를 옮길 수 있음: 페이지 키와 원문 페이지 인덱스 일치 검사 추가.
- 잘못된 달력 날짜·예산 정책 우회: 입력 검증 및 회귀 테스트 추가.

모듈은 테스트를 먼저 추가해 실패를 확인한 뒤 구현했다. 제품 동작을 추정해서 테스트 통과로 기입하지 않았다.

## PRD 검증 계약과의 관계

| 계약 | 이번에 확인한 부분 | 아직 확인하지 않은 부분 |
|---|---|---|
| K07·K08·K09·K18 | 순수 함수의 배정·예외·시간 부족·분량 보존 | 주간 자동 재계획, 실제 학습시간 추정, 학생 화면·복귀 경험 |
| K10·K13·K14·K17 | 관측 상태 분리, 자기보고·도움 정보 보존, 계획 버전 충돌 | 알림 제공자/장치 관측, 지연 과제 생성·수행 판정 |
| K03 | 외부 전송 동의·권리 조건의 순수 판정 | 실제 제공자 전송·철회·삭제 처리 |
| K04·K05·K21–K24 | 페이지 결과 상태, 해시·버전·쪽수 필드, 부분 준비·중복 방지 | 실제 PDF 추출/OCR, 원본 해시 계산, 표·수식 보존 정확도, 검색 색인 |
| K25 | 문서를 명령으로 실행하는 경로가 없는 데이터 처리 | LLM 연결 뒤 프롬프트 주입 방어와 HTML 렌더링 보안 |
| 나머지 및 K01–K25 전체 | 제품 전체 테스트 미실행 | 계정, 화면, 알림, 삭제·내보내기, 채점, 실제 학생 학습 |

검증 필드가 true라는 값과 실제 원본 대조를 구분한다. 현재 자료 모듈은 검증 결과를 받는 계약이며 검증자가 아니다. [사용법·한계](local-core.md)를 함께 읽는다.

## 남은 운영 위험

저장은 평문이며 암호화·다중 사용자·장기 백업·비정상 종료 잠금 복구·운영체제 장애 시험은 없다. 5 MiB를 넘으면 원본을 보존하고 쓰기를 중단한다. 사용자 자료를 받을 운영 서비스로 배포하기 전에 별도 보완이 필요하다. macOS/Linux와 Node.js 22 실행은 이번에 확인하지 않았다.
